Attendance Control

O aplicație desktop locală pentru pontaj: angajații își scanează cartela cu cod de bare la un kiosk, iar aplicația validează și înregistrează automat intrarea și ieșirea în timpul schimbului. Fără cloud obligatoriu, fără conturi pentru angajați.

01 Ce este Attendance Control

Un punct de pontaj complet local, proiectat pentru a rula pe un PC de atelier sau recepție, cu un scanner de coduri de bare și un ecran tactil.

🏭

Gândit pentru atelier

Rulează offline, pornește direct în kiosk și nu cere angajaților niciun cont sau PIN. Tot ce trebuie este cartela tipărită.

🔒

Datele rămân la tine

Toate înregistrările ajung într-un singur fișier SQLite local (attendance.db). Sincronizarea cu un server LAN este opțională.

📊

Gata de raportare

Rapoarte cu totaluri, export Excel pe 5 foi, exporturi programate automat, copii de siguranță și jurnal de audit.

Pentru cine este

Producție în ture, depozite, recepții și orice loc unde oamenii trebuie să „bifeze” intrarea și ieșirea fără să atingă un calculator.

04 Ecranul de kiosk

Aplicația pornește direct în kiosk, pe tot ecranul. Angajații nu se autentifică niciodată — văd doar rezultatul scanării.

Ce se întâmplă la o scanare
  1. Angajatul trece cartela peste scanner. Nu este nevoie să atingă ecranul.
  2. Kioskul afișează rezultatul aproximativ 2,5 secunde: ✓ CLOCK IN ✓ CLOCK OUT sau un motiv de respingere.
  3. Revine automat la starea READY pentru următorul angajat.
Fără acces la date din kiosk

Ecranul de kiosk nu expune pontaje, rapoarte, configurare sau administrarea bazei de date. Pentru orice operațiune de administrare este necesară autentificarea.

08 Schimburi

Un schimb definește fereastra în care o scanare este acceptată. Fără un schimb activ, scanările sunt respinse cu INVALID_SHIFT.

CâmpSemnificație
NumeEtichetă scurtă, unică (ex. Schimb 1, A)
StartOra de început (HH:MM)
EndOra de sfârșit. Dacă end ≤ start, schimbul este tratat ca de noapte
Early clock-in (min)Câte minute înainte de start se poate intra. Implicit 60
Earliest clock-out (min)Câte minute înainte de sfârșit se poate ieși. Implicit 10
ActiveDoar schimburile active sunt folosite la validare
Exemplu: schimb 07:00 – 15:00
06:00
Cea mai devreme intrare = 07:00 − 60 min. Înainte de 06:00 → CLOCK_IN_TOO_EARLY
14:50
Cea mai devreme ieșire = 15:00 − 10 min. Înainte de 14:50 → CLOCK_OUT_NOT_ALLOWED
22:00→06:00
Schimb de noapte: intrare la 21:30 și ieșire la 06:03 a doua zi sunt acceptate
Nu există „prea târziu” la intrare

Un angajat se poate ponta la 13:40 dacă nu are sesiune deschisă — este tratat ca începutul (întârziat) al turei. Doar ieșirea prea devreme și intrarea prea devreme sunt respinse.

Ora reală a scanării este mereu păstrată

Timestampul scanării nu este niciodată înlocuit cu ora planificată a schimbului. O scanare respinsă nu modifică nicio sesiune, dar rămâne în scanări brute și în excepții.

09 Rotirea săptămânală a schimburilor

Schimburile pot roti între echipe în fiecare luni. O rotire este un ciclu ordonat de schimburi; fiecare membru avansează o poziție în ciclu în fiecare săptămână.

Cum arată ciclul
SăptămânăAngajat AAngajat BAngajat C
1Schimb 1Schimb 2Schimb 3
2Schimb 3Schimb 1Schimb 2
3Schimb 2Schimb 3Schimb 1
4Schimb 1Schimb 2Schimb 3 (se repetă)
Configurare
  1. Creează schimburile care participă la rotire (secțiunea 8).
  2. Adaugă rotirea în pagina Shift Rotations: denumește-o și construiește ordinea cu Add, Up / Down și Remove. Sunt necesare minimum două schimburi, fără repetări.
  3. Atribuie membrii din pagina Employees: alege Rotation, apoi Starting shift (today) — schimbul pe care angajatul este chiar acum, care trebuie să facă parte din rotire.
Ce se actualizează automat
  • Lista angajaților, exportul Excel și validarea scanărilor folosesc schimbul care se aplică săptămânii curente.
  • Sesiunile din trecut păstrează schimbul înregistrat la momentul pontării.
  • No rotation readuce angajatul la schimbul fix.
  • Activate / Deactivate suspendă toată rotirea; membrii revin la schimbul fix.

11 Coduri de bare

Fiecare angajat primește o cartelă cu un cod de bare Code 128 care conține exclusiv ID-ul intern.

Reguli
  • Payload: doar ID-ul, ex. EMP000421
  • Fișier: barcodes/EMP000421.png
  • Format: Code 128, lizibil de scannere Honeywell
  • Tipărește, apoi dă fiecare angajat cartela lui
Confidențialitate

Codul de bare nu trebuie să conțină niciodată numele, departamentul, funcția sau parole. Codul de bare al angajatului nu este o credențială de administrator.

Generare din cod
from app.barcode import generate_barcode

cale = generate_barcode("EMP000421")   # -> barcodes/EMP000421.png
Dependență necesară

Generarea codurilor de bare are nevoie de python-barcode[pillow]. Dacă Pillow lipsește sau este instalat incomplet, butonul va raporta o eroare.

12 Scannere & terminale

Managerul de scannere deschide fiecare dispozitiv COM activat separat, citește linia codului de bare, identifică scannerul de origine și trimite evenimentul către motorul de pontaj. Nu depinde de focusul tastaturii.

Structura pe două niveluri

Terminale

Un terminal este o locație fizică: „Recepție”, „Poarta 1”, „Atelier”. Adaugă unul pentru fiecare loc în care se scanează.

Scannere

Fiecare scanner este un dispozitiv în mod USB Serial / COM. Un terminal poate avea mai multe scannere (o ușă de intrare și una de ieșire, sau două uși pe același terminal).

Câmpurile unui scanner
CâmpSemnificație
Scanner IDNume unic, ex. SCAN1 — apare în Live Scans
TerminalTerminalul din care face parte
COM portex. COM3 pe Windows, /dev/tty.usbserial-… pe macOS
Baud rateImplicit 9600 — trebuie să corespundă dispozitivului
EnabledDa = aplicația menține un thread de ascultare pe acest port
DescriptionText liber
Status și diagnostice
  • Coloana de status — Connecting → Connected / Offline. La deconectare, aplicația scrie în jurnal și reîncearcă la fiecare 5 secunde, fără repornire.
  • Test Port — deschide portul COM al scannerului selectat pe un thread separat și raportează succesul sau eroarea (selectează un rând de scanner, nu de terminal).
  • Test Scanner Input — simulează o scanare direct prin motorul de pontaj; alege un angajat real ca să vezi o intrare acceptată.
Simulatorul de scanner
python3 scanner_simulator.py
  1. Se creează automat un prim port de scanner; apasă + Add scanner port pentru fiecare scanner suplimentar. Fiecare rând afișează o cale de dispozitiv (ex. /dev/ttys005).
  2. În aplicație, adaugă câte un scanner în Terminals & Scanners pentru fiecare cale, cu Enabled = Yes. Folosește același terminal pentru mai multe căi, ca să simulezi mai multe scannere pe un terminal.
  3. Trimite scanări: Scan now / Enter, listă în bloc cu Send list, Repeat selected N times sau Spread across scanners pentru rotire pe toate porturile.
Pe Windows

Folosește un driver de tip com0com și introdu COM-ul emitent pentru fiecare port adăugat (ex. CNCA). Simulatorul nu atinge niciodată baza de date de pontaj.

13 Reguli de validare

Motorul de pontaj decide pentru fiecare scanare dacă este acceptată, ce acțiune reprezintă și — dacă este respinsă — de ce.

SituațieRezultatCod
Codul de bare nu corespunde niciunui angajat Respins, înregistrat ca excepție UNKNOWN_BARCODE
Angajat dezactivat Respins INACTIVE_EMPLOYEE
Fără schimb activ sau fără schimb atribuit Respins INVALID_SHIFT
Același angajat scanează în fereastra de duplicat (~5 s) Respins DUPLICATE_SCAN
Intrare mai devreme de start − minutele de intrare devreme Respins CLOCK_IN_TOO_EARLY
Ieșire mai devreme de sfârșit − minutele de ieșire minimă Respins CLOCK_OUT_NOT_ALLOWED
Altfel, fără sesiune deschisă Acceptat CLOCK IN
Altfel, cu sesiune deschisă Acceptat CLOCK OUT
Duplicatul de scanare

O a doua scanare a aceluiași angajat în intervalul de duplicat (implicit 5 secunde, configurabil în config.json) este respinsă. Aceasta previne scanarea accidentală de două ori a aceleiași cartele.

Toate încercările sunt păstrate

Aplicația reține fiecare scanare, inclusiv cele respinse: cod necunoscut, angajat inactiv, prea devreme și duplicate. Vezi pagina Exceptions pentru lista completă a respingerilor.

Configurare

config.json conține doar setări, nu înregistrări de pontaj:

{
  "site_name": "Company",
  "timezone": "Europe/Bucharest",
  "duplicate_scan_seconds": 5,
  "ui_theme": "dark",
  "default_export_directory": "exports"
}

Datele de pontaj sunt în attendance.db, nu în JSON.

Exportul Excel

Exporturile sunt registre .xlsx reale, denumite Attendance_YYYY-MM-DD.xlsx, cu cinci foi:

  1. Attendance Summary — sinteza prezenței
  2. Raw Scans — toate scanările brute
  3. Exceptions — respingerile
  4. Employees — lista angajaților
  5. Foile selectate suplimentar în dialogul de export
Copii de siguranță

Copiile au nume de forma backup/attendance_YYYYMMDD_HHMMSS.db. Restaurarea creează mai întâi o copie de siguranță a bazei curente, apoi o înlocuiește pe cea activă. Repornește aplicația după restaurare.

Nu șterge attendance.db dacă ai nevoie de istoric

Fă întâi o copie de siguranță. Copiile, jurnalele, exporturile și baza de date pot conține informații personale de pontaj — restricționează accesul la foldere folosind permisiunile normale de utilizator.

Exporturi programate și sincronizare
  • Automatic Exports — adaugă o sarcină cu oră, folder destinație și frecvență (zilnic / săptămânal pe zi / lunar pe zi). Coloana Next Run arată când va rula.
  • Synchronization — evenimentele care nu pot fi salvate sunt păstrate într-o coadă locală durabilă și reluate automat. Opțional, o adresă de server face ca fiecare scanare nouă să fie trimisă către o bază centrală, astfel încât mai multe kiosk-uri să împartă aceleași date.

15 Instalare & construirea EXE

Pentru utilizare normală este suficient python -m app.main. Pentru distribuire există un build care produce un singur executabil Windows.

Build simplu
build_exe.bat

Folosește PyInstaller și produce un singur fișier dist/AttendanceControl.exe, cu tot ce este necesar inclus. Copiază în dist/ și documentația: LICENSE.txt, README.md, GUIDE.md.

Build de producție (versionat + semnat)
python build_app.py                  # full build: PyInstaller + version + sign + package
python build_app.py --sign-existing  # sign/package the already-built EXE (fast)
python build_app.py --no-sign        # skip signing (macOS/Linux)
python build_app.py --onedir         # folder build instead of a single file
Rezultate

dist/

AttendanceControl.exe semnat, cu metadate Company / Product / FileVersion, plus documentația alături.

distribution/

AttendanceControl_v1.0.0/ și arhiva .zip — pachetul gata de livrare.

dist/certificates/

Certificatul de semnare și un instrument de încredere „într-un click”.

Certificat auto-semnat

Certificatul este auto-semnat (creat o singură dată pe PC-ul de build), deci este gratuit. Alte PC-uri Windows nu îl au în lista de încredere și pot afișa „Unknown publisher” — asta înseamnă doar că editorul nu este încă de încredere, nu că fișierul este nesigur. Pentru încredere completă, rulează o dată pe fiecare PC, ca Administrator:

powershell -ExecutionPolicy Bypass -File certificates\trust_certificate.ps1

Pe domeniu, distribuie același .cer prin Group Policy (Trusted Root Certification Authorities).

EXE-ul se construiește doar pe Windows

Un executabil Windows nativ trebuie construit și testat pe Windows; macOS nu poate produce .exe prin acest script. Aplicația își stochează baza de date, jurnalele, copiile de siguranță, exporturile și coada offline în folderul din care rulează EXE-ul.

16 Depanare

Cele mai frecvente situații și rezolvarea lor.

ProblemăRezolvare
ModuleNotFoundError: PySide6 Rulează python3 -m pip install -r requirements.txt din folderul proiectului.
Kioskul afișează UNKNOWN_BARCODE ID-ul scanat nu este un angajat (sau angajatul a fost șters). Creează angajatul / tipărește codul de bare corect.
Scanare respinsă DUPLICATE_SCAN Același angajat a scanat de două ori în ~5 s — așteaptă și scanează din nou.
Scanare respinsă CLOCK_IN_TOO_EARLY Prea devreme: cea mai devreme intrare = startul schimbului − minutele de intrare devreme.
Scanare respinsă CLOCK_OUT_NOT_ALLOWED Prea devreme pentru ieșire: cea mai devreme ieșire = sfârșitul schimbului − minutele de ieșire minimă.
Scannerul apare Offline Verifică calea COM, baud rate-ul, driverul și că niciun alt program nu a deschis portul. Aplicația reîncearcă la fiecare 5 s.
„Select a row first” Apasă mai întâi pe un rând din tabel, apoi pe buton.
Generarea codului de bare eșuează Verifică instalarea python-barcode[pillow]; un Pillow incomplet face ImageWriter indisponibil.

17 Cum se refac capturile de ecran

Toate imaginile din această pagină sunt generate automat dintr-o bază de date demonstrativă, printr-un script inclus în proiect. Nu conțin date reale de angajați.

Instrumente incluse
FișierRol
docs/tools/capture_screenshots.py Creează o bază demo, pornește interfața reală și scrie toate PNG-urile în docs/screenshots/
docs/tools/run_demo.py Pornește aplicația completă pe o bază demo izolată (.demo/), fără să atingă datele reale
Regenerarea imaginilor
# all captures (Windows, real desktop session)
.venv\Scripts\python.exe docs\tools\capture_screenshots.py

# only specific images
.venv\Scripts\python.exe docs\tools\capture_screenshots.py --only 03-dashboard --only 11-raport

# start the demo app for manual exploration
.venv\Scripts\python.exe docs\tools\run_demo.py --fresh
Siguranța datelor

Ambele scripturi lucrează exclusiv pe o bază de date temporară (docs/.capture/ respectiv .demo/). Fișierul de producție attendance.db, jurnalele și exporturile reale nu sunt atinse niciodată.

Vizualizarea paginii

Pagina este HTML + CSS static, fără dependențe externe. Deschide docs/index.html în orice browser, sau pornește un server local: 

python -m http.server 8000 --directory docs
# then open http://localhost:8000/
